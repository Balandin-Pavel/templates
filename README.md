# generator — утилита-шаблонизатор

Консольная утилита на C++ для генерации текстовых документов из шаблона и файла с данными. Заменяет метки вида `{{ variable_name }}` в шаблоне на значения, заданные в отдельном файле `key=value`.

Реализовано на «голом» C++ без STL-контейнеров, `std::string` и `std::regex` — только `<fstream>`, `<iostream>`, `<cstring>` и статические буферы `char[]`.

## Возможности

- Подстановка меток `{{ variable_name }}` значениями из файла данных.
- Пробелы внутри фигурных скобок игнорируются: `{{name}}`, `{{ name }}`, `{{  name  }}` — эквивалентны.
- Пробелы вокруг `=` в файле данных игнорируются: `key = value` и `key=value` равнозначны.
- Парсинг файла данных в формате `KEY=VALUE`, одна пара на строку.
- При повторном определении ключа побеждает **последнее** встретившееся значение.
- Символы `/ - + = : ^ ! ? ,` внутри `{{ }}` запрещены (см. коды возврата, код `5`).
- Вывод результата в файл (`--output`) или в стандартный поток вывода, если флаг не указан.
- Диагностика ошибок через коды возврата процесса.


## Формат файла данных


| Параметр | Значение |
|---|---|
| Разделитель ключа и значения | `=` (пробелы вокруг — опциональны) |
| Максимальная длина буфера ключа/значения | 128 байт (буфер `char[128]`, фактически доступно 127 символов) |
| Максимальное число пар ключ-значение | 1024 |
| Кодировка строк | обычный текст; концы строк `\n` и `\r\n` поддерживаются одинаково |


## Требования

- Компилятор с поддержкой C++23 (в `CMakeLists.txt` используется `cxx_std_23` / `CMAKE_CXX_STANDARD 23`).
- CMake ≥ 3.10.
- Доступ в интернет при первой конфигурации тестов — `tests/CMakeLists.txt` тянет GoogleTest 1.16.0 через `FetchContent` с GitHub.

## Сборка

Все команды выполняются из **корня репозитория** (папка, где лежит верхнеуровневый `CMakeLists.txt`).

### Через CMake (рекомендуется, включает тесты)

```bash
mkdir -p build
cd build
cmake ..
cmake --build .
```

Артефакты:
- `build/generator` (или `generator.exe` на Windows) — сама утилита;
- `build/tests/generator_tests` — тестовый бинарник на GoogleTest.

Собрать только утилиту, без тестов:

```bash
cmake --build build --target generator
```

### Напрямую через компилятор (без CMake, без тестов)

Если CMake недоступен, утилиту можно собрать одной командой:

```bash
g++ -std=c++23 -O2 -o generator main.cpp
```

(если компилятор не поддерживает `c++23`, подойдёт и `-std=c++17` — фичи новее C++17 в `main.cpp` не используются).

## Использование

```
generator --template=path --data=path [--output=path]
```

| Короткий флаг | Длинный флаг | Обязательный | Описание |
|---|---|:---:|---|
| `-t <path>` | `--template=<path>` | ✅ | Путь к файлу-шаблону |
| `-d <path>` | `--data=<path>` | ✅ | Путь к файлу с данными |
| `-o <path>` | `--output=<path>` | ❌ | Путь к результирующему файлу (по умолчанию — вывод в stdout) |

Короткие флаги (`-t`, `-d`, `-o`) ожидают значение отдельным аргументом, длинные (`--template=`, `--data=`, `--output=`) — через `=` без пробела. Смешивать формы можно.

### Примеры

Из корня репозитория (утилита ещё не собрана в `build/`, используем `g++`-сборку рядом):

```bash
g++ -std=c++23 -o generator main.cpp

./generator --template=example/template.txt --data=example/data.dat --output=example/result.txt
```

Если утилита собрана через CMake (бинарник в `build/`), пути к файлам удобнее указывать относительно корня:

```bash
./build/generator --template=example/template.txt --data=example/data.dat --output=example/result.txt
```

Короткие флаги:

```bash
./build/generator -t example/template.txt -d example/data.dat -o example/result.txt
```

Без `--output` — результат печатается в stdout:

```bash
./build/generator --template=example/template.txt --data=example/data.dat
```

Готовый пример входных/выходных файлов лежит в директории [`example`](example).

## Коды возврата

| Код | Значение |
|---|---|
| `0` | успешное завершение |
| `1` | в шаблоне встретилась метка `{{ ... }}`, для которой нет ключа в файле данных |
| `2` | не переданы обязательные аргументы `--template`/`--data` |
| `3` | ошибка ввода-вывода (файл данных или шаблон не открылся, либо не удалось открыть файл вывода) |
| `4` | синтаксическая ошибка в шаблоне: незакрытая метка `{{ ... ` без второй `}}` |
| `5` | в имени ключа внутри `{{ }}` встретился запрещённый символ (`/ - + = : ^ ! ?` или `,`) |

## Тестирование

Тесты (GoogleTest, позитивные и негативные кейсы из `tests/test_cases/`) собираются вместе с проектом через CMake:

```bash
cd build
ctest --output-on-failure
```

или напрямую (важно запускать из `build/tests/`, так как раннер обращается к утилите по относительному пути `../generator`, а к тест-кейсам — по `test_cases/`, которые CMake копирует рядом при конфигурации):

```bash
cd build/tests
./generator_tests
```

Структура одного тест-кейса (`tests/test_cases/positive/caseN/` или `.../negative/caseN/`):
- `template.txt` — входной шаблон;
- `data.dat` — файл данных;
- `expected.txt` — ожидаемый результат (только для позитивных кейсов).
